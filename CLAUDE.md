# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A hand-built static site generator in Node.js for **Raalmadu Wilpattu**, a jungle lodge on the edge of Wilpattu National Park, Sri Lanka. No framework, no runtime dependencies, no web fonts. Output is plain HTML/CSS/JS in `dist/`.

## Commands

```bash
npm install               # sharp (images) + puppeteer-core (QA)
npm run images            # fetch CC placeholders + generate responsive derivatives (one-off)
npm run images:optimize   # re-run only the optimiser after swapping source photos
npm run build             # render dist/
npm run serve             # preview on http://localhost:4173
npm run dev               # build + serve
npm run verify            # build + check + qa + audit — run before deploying
```

Individual audits (used inside `verify`):

- `npm run check` — static SEO audit of `dist/` (titles, descriptions, canonicals, headings, alt text, JSON-LD, sitemap, internal links). Fails on any error.
- `npm run qa` — headless-Chrome responsive layout at 360/390/768/1280/1680 px. `npm run qa:shots` also saves screenshots to `.qa/`.
- `npm run audit` — runtime audit: JS errors, failed requests, axe-core WCAG 2.1 AA, interaction smoke tests (nav, lightbox, booking hand-off, date sync, form validation, skip link). Fails on serious/critical only.
- `npm run images:sheet` — renders every image into one labelled grid at `.qa/contact-sheet.jpg` for spotting mismatched photos.

There is no test runner, linter, or type checker configured. The three audit scripts are the correctness gate.

## Architecture

The whole site is generated by `build.js` from data modules. Understanding the build pipeline is the fastest way to get productive.

### Build pipeline (`build.js`)

1. Loads `src/data/image-manifest.json` (generated by `npm run images`) and hands it to `components.js` via `setImageManifest()`. Every `picture()` call reads dimensions and LQIP data URIs from this manifest.
2. Imports page factories from `src/pages/` and calls them with the runtime data (rooms, LCP preload descriptor, credits, etc.). Each factory returns a `{ path, title, metaTitle, metaDescription, body, jsonLd, ... }` object.
3. Runs **guard rails** across the collected page objects — it collects *every* violation before failing so a bad build is fixed in one pass. Enforced invariants:
   - unique page paths
   - unique `<title>` values, all ≤ 65 chars
   - exactly one `<h1>` per page (counted by regex against `page.body`)
   - meta description length 70–165 chars
4. Cleans `dist/`, copies `public/` verbatim, inlines the minified `src/styles/main.css` into every page via the `__SITE_CSS__` sentinel in `layout.js`, and writes `src/scripts/main.js` to `dist/assets/js/`.
5. Renders each page through `renderPage()` in `src/lib/layout.js` and writes it to a directory-style clean URL (`/rooms/suite/` → `dist/rooms/suite/index.html`).
6. Generates `sitemap.xml`, `robots.txt`, `site.webmanifest`, and host configuration for Netlify (`_headers`, `_redirects`), Apache (`.htaccess`), and Vercel (`vercel.json`).

### Data-driven content

Text is data, not markup. To change what the site says, edit `src/data/`:

- `site.js` — **single source of truth** for the domain (`SITE_URL`), contact, geo, policies, form provider. Every canonical, OG URL, sitemap entry and JSON-LD node derives from here. Values tagged `VERIFY:` are placeholders that must be confirmed with the hotel owner before launch (see README → "Before you launch").
- `rooms.js` — room inventory. Adding a room automatically creates its page, card, sitemap entry, and `HotelRoom` JSON-LD node.
- `content.js` — facilities, experiences, offers, FAQs, testimonials. Adding an FAQ automatically extends the `FAQPage` schema.
- `images.js` — image registry: `alt` text + `aspect`. `alt` is written once and reused everywhere via `picture()`; an image with no registry entry throws at build time. `aspect` drives both the crop in `scripts/optimize-images.js` and the intrinsic `width`/`height` in the HTML — that pairing is what keeps CLS at zero.
- `image-manifest.json` — **generated**, not hand-edited. Contains real dimensions and LQIP data URIs. Rebuild with `npm run images:optimize`.

### The shell (`src/lib/layout.js`)

Every page renders through `renderPage()`, which is what guarantees each page has — without exception — a unique title, a meta description, a self-referencing absolute HTTPS canonical, an explicit `index, follow` robots directive, OG/Twitter cards with an absolute image URL, and a connected JSON-LD graph. Don't emit `<head>` markup from page modules.

### JSON-LD graph (`src/lib/schema.js`)

Nodes use stable `@id`s so the graph is connected across pages:
- `{origin}/#hotel` — the business (Hotel/LodgingBusiness), site-wide canonical
- `{origin}/#website` — the site
- `{pageUrl}#webpage` — the individual page, linked back to hotel + website
- `{pageUrl}#breadcrumb` — breadcrumb trail

**Deliberately NOT emitted: `aggregateRating`.** The 9.0/10 shown in the UI comes from Booking.com; Google's policy treats third-party ratings on a `LocalBusiness` as ineligible and marking it up risks a manual action. Keep it in the UI, keep it out of the graph.

### Components (`src/lib/components.js`)

- `picture(key, opts)` — responsive `<picture>` with AVIF → WebP → JPEG. Always emits `width`/`height`, always emits `alt` from `IMAGES[key]`. Throws if the key is unknown. Pass `priority: true` for the LCP image only.
- `esc()` and `attr()` — always escape user-visible strings when hand-writing markup.
- Section helpers take an explicit heading level; the SEO audit fails if any page skips a level (h2 → h4).

### Performance invariants worth preserving

- Stylesheet is inlined (~22 KB minified, ~5 KB over the wire) rather than linked — trades one request for larger HTML and keeps the CSP free of the inline event handler the async-stylesheet trick needs.
- Hero image is preloaded with `<link rel="preload" as="image" type="image/avif" imagesrcset>` and carries `fetchpriority="high"`. Home passes its preload descriptor via `preloadFor('hero-lodge', ...)`; other pages declare `preloadImageKey` on their page object.
- No web fonts. Do not add any.
- Sticky header uses `IntersectionObserver`. Don't add scroll handlers that force layout.

### CSP and third-party scripts

Content-Security-Policy in `buildHeaders()` (also mirrored in `.htaccess` / `vercel.json`) is `script-src 'self'` only. Any third-party script (booking engine, form provider, analytics) must have its origin added there or it will be blocked. The `/booking/` page has a `<div id="booking-engine" data-booking-engine>` mount point ready — wire providers up in `src/scripts/main.js`.

### Accessibility

The palette is checked against WCAG 2.1 AA (4.5:1 for normal text). The accent colour `--clay` is `#a05a3c` specifically because the warmer `#b06a4a` it started as only reached 4.19:1 behind white button text. If you lighten it, re-run `npm run audit`.

## Deployment

`dist/` is a plain static directory; the generated host-config files make it deployable to Netlify / Cloudflare Pages, Vercel, or Apache/cPanel without further work. Nginx needs manual config (`try_files $uri $uri/index.html =404`, HSTS, apex → www redirect). See README → "Deployment".

## Placeholder content

Every photograph on the site is a Creative-Commons placeholder credited on `/image-credits/` — they depict the region, not the property. Room, pool and dining images in particular do **not** show the actual rooms. To swap in real photography, drop files into `assets/images/src/` using the existing filenames, update `alt` in `src/data/images.js`, and run `npm run images:optimize && npm run build`. See README → "Photography".
